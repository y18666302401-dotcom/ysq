# 阶段 4：配音与对时

先配音、再做动画。动画的时长跟着真实配音走，否则画面和声音会越来越错位。

## 默认配音设置

用户已经测试并确定了以下设置，除非用户要求更改，一律照此执行：

| 项目 | 设置 |
|---|---|
| 服务 | Gemini TTS |
| 模型 | gemini-3.8-flash-tts |
| 音色 | Charon |
| 语气指令（style） | **不写**。实测加了语气指令后语气变刻意、语速被拖慢，默认演绎更好 |
| 节奏控制 | 只靠旁白文字本身：标点、破折号，以及停顿标签 `<short pause>`、`<long pause>` |

把这些设置写进 PROJECT.md 的"配音设置"一节。

## 运行环境检查（第一次配音前）

配音和对时脚本需要 Python 3.10 以上和 ffmpeg。先检查，缺什么告诉用户、征得同意后再安装：

| 系统 | 检查 | 安装 |
|---|---|---|
| Windows | `python --version`、`ffmpeg -version` | `winget install Python.Python.3.12`、`winget install Gyan.FFmpeg`，装完重开终端 |
| macOS | `python3 --version`、`ffmpeg -version` | `brew install python ffmpeg` |
| Linux | 同上 | 用系统包管理器安装 |

- **Windows 注意**：`python` 指向 `AppData\Local\Microsoft\WindowsApps\python.exe` 时只是微软商店的占位程序，没有真正安装，运行会直接退出（退出码 49 或弹出商店）。要按上表安装真正的 Python。
- Windows 和 macOS 上命令用 `python` / `python3` 按实际可用的写；下文统一写 `python`。
- 对时脚本第一次运行会自动下载 Whisper 语音识别模型（`small` 约 500 MB），提前告诉用户需要等待和联网。

**API Key：** 脚本先找环境变量 `GEMINI_API_KEY`，找不到就读取用户主目录下的 `.gemini_api_key` 文件。用户是编程新手，不要让用户自己去设置环境变量。第一次配音前，如果两处都没有 Key：
1. 请用户把 Key 发过来一次；
2. 由你把它写进用户主目录下的 `.gemini_api_key`（文件里只放 Key 本身，不加其他内容），并把权限设为仅本人可读：
   - Mac/Linux：`chmod 600 ~/.gemini_api_key`
   - Windows（PowerShell）：`icacls "$env:USERPROFILE\.gemini_api_key" /inheritance:r /grant:r "${env:USERNAME}:F"`
3. 之后不要在回复、日志或任何文件里显示 Key 的内容，也不要写进项目文件夹（项目可能会被分享或上传）。

用户再给新的 Key 时，追加到 `.gemini_api_key` 的新一行（每行一个，不覆盖旧的）。`tts_gemini.py` 会按顺序使用：前一个 Key 当天额度用完，自动换下一个。

## 调用额度

Gemini 3.8 Flash TTS 的**免费层每天只有约 10 次调用**（2026 年 10 月实测）。默认的整段生成每条视频只用 1 次；逐段生成时一个分镜就是一次调用，一条几分钟的视频就会超出。配音前先问用户是否已开通付费层：
- 已开通：正常生成。
- 未开通：告诉用户免费额度不够完成整条视频，建议开通付费层（成本见下）；用户坚持用免费层的话，按每天的额度分批生成，脚本遇到额度用完会自动停下并列出未完成的分镜，第二天用 `--only` 继续。
- 不要为了补齐而换用其他模型（如 Flash-Lite），前后音色会不一致。

参考成本（实测计费数据推算，付费层，2026 年底前价格）：每分钟成片配音约 0.02–0.03 美元，10 分钟视频约 0.2–0.3 美元；2027 年起价格翻倍。重录次数越多成本越高。

## 双语配音

两种语言各配一次，文件分开放：`audio/zh/`、`audio/en/`。下面的步骤对每种语言各做一遍，命令里的 `audio/` 换成 `audio/zh/` 或 `audio/en/`，`--lang` 分别填 `zh`、`en`。
- 英文的 beats.json 用 STORYBOARD.md 的"英文旁白"列，分镜 id 和中文完全相同。
- 音色默认同一个（Charon 能读中英文）；英文读得不自然时，告诉用户并建议换英文音色，由用户决定。
- 每期要两次整段生成，免费额度更紧，配音前照"调用额度"一节先问清。
- STORYBOARD.md 的时间码以中文版为准；英文版的真实时长记在表格后面（总时长、每个分镜的英文时长）。

## 生成步骤（默认：整段一次生成，不切分）

整条旁白用**一次请求**生成，音频不切分；分镜的起止时间靠语音识别对时得到。这样前后语气连贯，也只用一次调用额度。

1. **准备 beats.json。** 按 STORYBOARD.md 的分镜，把每个分镜的旁白原文整理成：
   ```json
   [{"id": "01", "text": "……"}, {"id": "02", "text": "……"}]
   ```
   旁白文字和 script.md 逐字一致（script.md 分段排版的话，按原文顺序合并）。

2. **停顿标签放在哪里。** 分镜是按画面切的，不是按句子切的，所以**不能在每个分镜分界处都加长停顿**：
   - 分界处在句末（句号、问号、感叹号）：脚本自动加 `<long pause>`。
   - 分界处在句子中间（逗号、冒号，或没有标点）：**不加任何停顿标签**，让句子自然读完。实测在句子中间插长停顿，会把一句话读成两截。
   - script.md 的段落之间、重大转折处，可以在 beats.json 的文字里手动加一个 `<long pause>`。
   - 停顿标签只放在 beats.json 里，不写进 script.md 和字幕。

3. **生成整段音频。**
   ```bash
   python <skill目录>/scripts/tts_gemini.py audio/beats.json audio/ --whole --pause short
   ```
   `--pause` 控制句末分镜分界处的停顿：`long` 的实际长度不稳定（2026-10 实测一条片子里每句后停 1.6–2.6 秒，整片被拖慢 15 秒以上，用户嫌停顿太长），**默认用 `short`**（句间约 0.5–1 秒）；结尾问题前要留一拍时，在那一句的 beats 文字前手写 `<long pause>`。
   输出 `audio/narration.wav`（整段）和 `audio/narration_text.txt`（实际发送的文字，含停顿标签）。

4. **对时并逐段检查。**
   ```bash
   python -m pip install faster-whisper scipy numpy   # 首次需要；Linux 系统 Python 报 externally-managed 时加 --break-system-packages 或改用虚拟环境
   python <skill目录>/scripts/align_shots.py audio/beats.json audio/narration.wav audio/ --lang zh
   ```
   `--lang` 填这一版的语言（中文版 `zh`，英文版 `en`）。脚本用语音识别得到每个字（英文为每个字母）的发音时刻，和旁白原文对齐，输出：
   - `audio/shots.json`：每个分镜的起止时间、说话的起止时间、每个关键词的时刻（动画和音效都从这里读时间）
   - `audio/words.json`：词级时间戳
   - 检查报告，逐项看，**不能只看总时长**：
     - 每个分镜的说话窗口里都有人声（RMS 不低于 -50 dBFS）
     - **超过 1.5 秒的静音**逐个列出：模型对 `<long pause>` 的处理前后可能不一致（实测同一段音频里，前半段停顿约 1 秒，后半段变成 3–4.5 秒）
     - 识别结果和原文对不上的地方逐个列出：可能是读错、漏读，或多出一小段杂音（实测出现过约 0.2 秒的重复起头）

5. **处理检查出的问题，然后告诉用户。**
   - 有分镜没声音、读错或漏读：改写那句的写法后重新生成整段（见下面的“读错时的处理”）。
   - 静音过长、多出杂音：**把问题和建议告诉用户，由用户决定**是重新生成整段（多花一次额度），还是把那几处静音缩短到约 1 秒、把杂音静音（属于剪辑音频，要用户同意）。不要自己判断“留着也行”而不说。

6. **更新时间码。** 用 shots.json 更新 STORYBOARD.md 的时间码和总时长。

**备用方式：逐段生成。** 用户要求时，去掉 `--whole` 参数，脚本会逐个分镜生成 `audio/beat-XX.wav` 并记录时长。逐段检查有声；如果要从整段音频切分，不要在输出端同时用 `-ss` 和淡入淡出滤镜（会导致后续片段全部静音），改用输入端定位或 atrim 滤镜。

## 语速、音高和结尾那一拍

- **用户嫌慢**：不要加语气指令（会更慢、更刻意）。生成后整段用 ffmpeg `atempo` 提速，**不超过 1.1 倍**（音高不变），保留原始文件为 `narration_raw.wav`，然后重新对时。2026-10 实测 1.08 倍后中文约 5.1 字/秒、英文约 214 词/分钟，用户接受。
- **音高每次随机**（同一音色 111–128 Hz 都出现过），提速不改变音高。每条都测中位音高（自相关取中位数即可）告诉用户；用户嫌高时再生成一条，挑低的那条，但先看有没有多读（实测出现过凭空多出一个 "And"），有多读的不用。
- **结尾问题前的那一拍可能没读出来**（英文更常见）：在上一句结束和问题开始之间插 0.8 秒静音（属于剪辑音频，先告诉用户）。插完再对时时，最后一个分镜的逐字时间会变成平均插值；改为**对未插静音的文件对时，再把切点之后的时间整体加 0.8 秒**写回 shots.json 和 words.json。

## 停顿点

**这一步必须停下来，不能跳过。** 把两个版本的总时长、检查报告和整段音频交给用户，请用户分别试听，重点检查：多音字和数字的读法、人名地名是否读对、停顿是否合适。

读错时的处理：先改写那句话的写法（比如把"1871年"写成"一八七一年"、给容易读错的字换个说法），重新生成那一段，不要用语气指令去纠正。改写涉及旁白原文时，要征得用户同意，并同步更新 script.md。

## 锁定音频

用户确认后，audio/ 里的文件视为锁定。之后某一段需要重录时：
1. 整段生成时，改好文字后重新生成整段，再跑一次 align_shots.py；逐段生成时只重录那一段：`python <skill目录>/scripts/tts_gemini.py audio/beats.json audio/ --only 05`
2. 重新生成词级时间戳；
3. 更新 STORYBOARD.md 的时间码；
4. 告诉用户哪些分镜的动画需要重新对时（见 05-animation.md），并记进 TODO.md。

AI 配音每次生成的语速都可能略有不同，所以绝不能"先做好动画，再重新生成音频"而不重新对时。
