# 阶段 2：旁白脚本

以纪录片编剧的身份，根据 PROJECT.md 里的选题、时长和语言，写一份完整的连续旁白稿。

## 写之前

1. **查证。** 联网收集这个故事的关键事实，每条事实连同来源链接记进 `NOTES.md`。脚本里出现的每个日期、人名、数字都必须能在 NOTES.md 找到出处。
2. **算长度。** 按自然纪录片语速估算旁白长度：中文约 220–260 字/分钟，英文约 140–160 词/分钟。不用机械凑字数，优先保证口播自然和故事完整。

## 脚本要求

**只写会被读出来的内容。** 不要镜头说明、分镜编号、画面提示、剪辑提示、BGM 说明、章节标题或括号里的导演备注，这些在分镜阶段单独做。

**开头直接进故事。** 不要用"你知道吗""今天我们来聊聊""欢迎来到"。从一个具体日期、地点、人物、异常事件、令人疑惑的细节，或一个关键数字或决定切入，让观众在前 10–20 秒内想知道"发生了什么、为什么、接下来呢"。

**开场钩子模板（每期必用，用户 2026-10-12 定）。** 开头 4–8 句按这个顺序写，约占 15–20 秒：

1. **具体时间 + 地点**："建安二十四年五月，汉中。"——具体日期让观众知道"这是真事"；不要用"很久以前""有一天"。时间只精确到史料能确认的程度（年、季、月、日都可）。
2. **处境**：一句交代当时的局面或压力（"曹操的大军被刘备挡在山里，进退两难"）。
3. **人物 + 一个定义性细节**：名字加**一个**最能说明他是谁的细节（"全营最会猜曹操心思的人"）。只给一个，多了拖节奏，其余留到正文。
4. **他（或众人）的预期**：一句说出显而易见的预期（"他以为，这不过是又一次猜中谜底"）。预期是叙述者的推想时，措辞要像推想，不能写成史料。
5. **预期被打破 + 留悬念**：告诉观众结果很严重，但不说怎么发生的（"可这一次猜中之后，他只剩下几个月的命"）。观众知道"出事了"，不知道"为什么"，这个缺口撑起后面的正文。

常用的切入方式：**从故事里最紧张的那一刻切入，再倒叙**——开场停在关键时刻，第二段用一句"……是从……开始的"回到起点，讲完前因后用"再回到……"接回开场那一刻，再往下讲结局。故事本身是递进的（一件比一件严重）时也可以顺叙，但开场仍按上面 5 步写。

例（第 4 期《杨修一合酥》，用户确认）：
> 建安二十四年五月，汉中。曹操的大军被刘备挡在山里，进退两难。这天，曹操传下一道命令，只有两个字："鸡肋"。将官们面面相觑，没人懂是什么意思。只有一个人，已经开始收拾行装。他叫杨修，曹操的主簿，全营最会猜曹操心思的人。他以为，这不过是又一次猜中谜底。可这一次猜中之后，他只剩下几个月的命。
>
> 杨修猜谜，是从一扇门开始的。……再回到汉中。……

英文版同样套这 5 步（"May, 219 AD. Hanzhong, China. … Only one man was already packing. … But after this one, he had only months to live."）。

**有故事线，不是百科罗列。** 可参考：钩子 → 背景 → 事件开始 → 冲突升级 → 关键决定或转折 → 后果 → 更大的影响 → 结尾。不要为了套模板强行分段，故事自然流动最重要。

**因果和时间要清楚。** 多用"后来、与此同时、几天之后、但真正的问题是、正因为如此、然而、直到……、这意味着……、没人想到的是……"这类自然衔接，让观众一直跟得上。

**一句话一个主要信息。** 后面要按句拆成画面，所以每句都应有一个可视觉化的核心概念。但不要为此把语言写得机械破碎。

**多写看得见的东西。** 人物、建筑、地点、地图、报纸、档案、信件、合同、票据、产品、金钱、时间线、数据、交通路线、历史照片、关键物品、新闻标题。避免长时间停留在抽象观点上。

**语气克制。** 清晰、有故事感、信息密度高、通俗易懂。不要写成论文，也不要煽情或用短视频营销腔。

**有争议的信息要克制表达。** 用"据报道""调查人员认为""当时的记录显示""外界普遍认为"。

**按时长控制深度。**
- 60 秒以内：只保留一个核心事件和最强转折。
- **80–90 秒（默认）**：中文约 330–370 字，英文约 200–220 词。结构：开场钩子（上面的 5 步模板，15–20 秒）→ 极简背景（一两句，倒叙时就是"……是从……开始的"）→ 压力积累 → 关键瞬间（全片最长、最细的一段）→ 后果和规模 → 有余味的结尾。只讲一条主线，不展开人物生平和次要线索。
- 2–5 分钟：围绕一个主要故事，可加背景、冲突、结果。
- 5–10 分钟：可加更多人物、关键节点和第二层转折。
- 10 分钟以上：完整叙事，包括多个阶段、关键人物、冲突升级、转折和长期影响。
不要为了凑时长重复同一信息。

## 评论钩子（必做）

先读 `comment-hooks.md`。脚本里必须包含：
- **结尾主问题**：从故事里长出来、观众 5 个字以内就能回答（二选一 / 猜数字 / 站队 / 代入 / 亲身经历），旁白**停在问句本身**，后面不加"评论区告诉我"之类的引导（用户 2026-10-12 要求），引导交给画面上的提问卡和评论气泡；问题只说一次。问题依据的事实要在 NOTES.md 有出处；不拿伤亡做竞猜。
- **可选**：前 10 秒内一句预告（"看到最后，你来判断他错没错"）；关键瞬间之前一个二选一的中段预测。
- 钩子占用约 8–10 秒，算在目标时长内，压缩背景和后果段，不压缩关键瞬间。

## 结尾

不要简单总结全文。优先用以下之一：一个至今未解的问题、一个改变前文理解的新事实、关键人物最后的命运、一个至今仍存在的物品或建筑或文件、一个意外的后续、一个长期影响、一个简短有余味的事实。有余味的那句之后接结尾主问题（见上节）；问题本身也要有画面感，适合配一张提问卡停在最后一个画面上。

## 输出

写入 `script.md`，格式：

```
目标视频时长：
预计旁白长度：

【完整旁白脚本】
（连续、自然的旁白；按故事段落分段排版，方便用户审稿）

【评论钩子】
结尾主问题：……（选项 A / B）
中段预测：……（没有就写"无"）

【实际字数 / Word Count】
【预计配音时长】
```

分段只是为了审稿方便，不影响内容：配音时把各段按原文顺序合并，段落之间的停顿在 04-voice.md 里统一处理。

### 字幕重点词表 highlights.json

中英文脚本定稿时，同时在项目根目录写 `highlights.json`，供字幕标色（rules.md 第 3 节、`scripts/subtitles.js`）：

```json
{ "zh": { "name": ["朱厚照"], "place": ["宣府"], "date": [], "num": [], "key": ["威武大将军"] },
  "en": { "name": ["Zhu Houzhao"], "place": ["Xuanfu"], "date": [], "num": [], "key": ["Grand General"] } }
```

- 词要和旁白原文**一字不差**（英文不分大小写）；脚本改了，词表跟着改。
- 必写：故事里每个人名、地名，以及每段的关键转折词（"踢球""封官""被处死"这类一听就知道剧情拐了的词）。年份、朝代、世纪、带单位的数字自动识别，识别不到的（"十几年""四十二公里"这类写法）手动补进 date / num。
- 目标：全片约一半的字幕行有标色，但每行不超过 3 处。

## 英文版旁白

中文稿写完后，写一份英文旁白存进 `script_en.md`（格式同上，字数改为 Word Count，语速按英文约 140–160 词/分钟估算）：
- **按英语纪录片的说法改写，不逐字翻译。** 开头钩子、句子节奏、衔接词都按英语观众的习惯来；中文特有的表达（成语、四字格）换成自然的英文说法。
- **事实、结构、段落顺序与中文版完全一致。** 每一段对应中文的同一段，后面拆分镜时要逐段对上。不增删信息。
- **单位和数字按英语观众习惯**：美国题材用英制单位并在需要时补公制（例："2.3 million gallons"），日期写成英文格式。和中文版的数字口径必须一致（同一个事实）。
- 人名、地名用通行的英文写法。
- 评论钩子按英语习惯改写（"Being too clever, or picking the wrong side?"），同样停在问句，不加 "let me know in the comments"；问题和选项与中文版一致。
- 两个版本的时长尽量接近（差别在 15% 以内）；明显偏长时精简英文措辞，不删事实。

然后停下来请用户确认（中英文一起给）。确认后的 script.md 和 script_en.md 是后续所有阶段的唯一依据，之后不要再擅自改动；用户要求修改时才改，改一个版本时同步检查另一个。
