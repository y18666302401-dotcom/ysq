# 阶段 5：用 HyperFrames 制作动画

> **没有 HyperFrames 的环境**（例如 claude.ai 网页对话）：扁平插画画风改用 `scripts/flat_toolkit.js` 的 canvas → ffmpeg 渲染管线，示例见 `scripts/examples/carrington-10s/`，用法见 styles/flat.md 的“实现工具”。分镜时长、关键词时刻同样从 `audio/shots.json` 读取。

## 开始前

1. 读 `references/rules.md`、所选画风文件（默认画风读 hand-drawn.md 和 hand-drawn-cinematic.md；柔光动画读 glow.md 和 hand-drawn-cinematic.md；墨线贴纸读 ink-sticker.md 和 `scripts/examples/ink-sticker/`，人物用 `char34.js`，先看 `bucket-60fps/`），以及 PROJECT.md 的"本期视觉设定"。默认画风先读示例 `scripts/examples/molasses-15s/`（分层合成和调色）、`scripts/examples/fine-hand/`（画法）和 `scripts/examples/atmos/`（大气景观镜头、运动语汇）；柔光动画读 `scripts/examples/glow/` 和 `scripts/examples/atmos/`；有人物动作再读 `scripts/examples/character-rig/`。
2. 调用 `/hyperframes` skill，按它的规范写 composition。命令行操作看 `/hyperframes-cli`，动画写法（GSAP 等运行时、镜头推拉、转场）看 `/hyperframes-animation` 和 `/hyperframes-keyframes`，混音看 `/hyperframes-audio`。具体写法以 skill 为准，不要凭记忆写，版本更新后 API 可能变化。
3. 画布尺寸按 PROJECT.md 的画幅。帧率按画风文件（柔光动画 24fps 平滑；逐帧手绘输出 24fps 并一拍二；墨线贴纸 60fps；其余默认 30fps）。每个分镜的时长等于 STORYBOARD.md 里配音后的真实时长。
4. 不使用 3D，所有画面用 2D 绘制（Canvas、SVG、HTML），空间感用分层视差和镜头推拉表现。

## 参考资料：画到具体的东西时现查

不单独搜集素材，也不登记许可（参考图不上画面）。做到某个分镜时：
- **通用物件**（比萨盒、手机、办公室、法庭内景）凭常识画，不查。
- **具体的东西**现查一下再画：某款车型的外形、某个地标或建筑、某个年代的制服、警车、招牌、器物。联网搜图，看清关键特征（轮廓、比例、标志性细节）就画，图片放进 `assets/ref/` 方便同一元素前后一致。
- **地图和海岸线**一律用真实地理数据（如 Natural Earth）生成轮廓再按画风上色，不凭印象画。
- **AI 生成图片**只有用户明确同意后才能用，不做成以假乱真的写实照片。
- 画面必须一眼看得出是插画或图示，不伪装成历史照片或真实报纸。

## 确定性

渲染时会逐帧跳到指定时间截图，动画必须是时间的纯函数：

- 禁止用 `Math.random`、`Date.now`、`requestAnimationFrame` 控制动画。需要随机的形状、抖动，用固定种子的伪随机数。
- Canvas 自绘写成 `render(t)`，监听 HyperFrames 的 `hf-seek` 事件，用事件里的时间重画当前帧。具体接入方式先查 `/hyperframes` skill。
- 物理效果（摆动、滑动、坠落、碰撞）用固定步长预先积分，按时间查表取值。

## 双语：同一套动画，渲染两次

- 动画代码只写一套，用一个语言参数切换：分镜时长读 `audio/<语言>/shots.json`，跟词走的动作读 `audio/<语言>/words.json`，字幕读对应语言的旁白。
- **画面里的所有文字**（标签、日期卡、数字单位、名牌、地图地名、片尾频道名）只出现当前语言，不中英并排；不写死在代码里，放进项目根目录的 `strings.json`：`{"tag_volume": {"zh": "870 万升", "en": "2.3M gallons"}}`。英文通常更长，排版要按两种语言里较长的那个留空间。
- **跟词走的动作**用"提示词"定位：在 strings.json 旁边维护 `cues.json`，写明每个动作对应的词在两种语言里各是什么（`{"tag_volume": {"shot": "05", "zh": "八百多万升", "en": "2.3 million gallons"}}`），从该语言 shots.json 里这个分镜的 chartimes 找到这个词的开始时刻。
- 字幕不显示标点符号（规则见 rules.md 第 3 节），在生成字幕时统一去掉，不改 shots.json 里的原文。
- 两个版本的分镜时长不同，所以每个分镜都必须按下面"音画同步"的写法做：动作集中在前段，结尾的稳定段吸收时长差异。
- **互动钩子的提问卡**（问题、选项、倒计时）同样进 strings.json，按 comment-hooks.md 第 4 节做：物理出场、A/B 用两种标色、评论气泡轻跳一次、结尾卡片停留到片尾，不放进右侧按钮栏和底部 450px。做完单独截一帧叠上平台界面的遮挡区示意检查。
- 招牌镜头和每 3–5 个分镜的预览先只看中文版；英文版在导出前统一抽查，重点看英文文字有没有溢出、跟词动作有没有对上。

## 音画同步

AI 配音的语速每次可能不同，所以动画的时间不要写死成固定秒数，而是从音频推导：

- **分镜时长**：从 `audio/shots.json`（整段配音对时后得到的每个分镜起止时间）读取，不要手填数字。
- **跟词走的动作**：盖章、标签弹出、红线连接、关键数字出现这类需要和某个词同步的动作，时间点从 `audio/words.json` 里那个词的开始时间读取，不要写"第 2.3 秒"。
- **其余动作**：入场和组装动作集中在分镜的前段，结尾的稳定段负责吸收时长变化。这样某段音频变长或变短时，只是稳定段长短不同，画面节奏不会乱。

做到这三点，重录某段配音后，只要重新读取时长和词级时间戳，动画就会自动对上。重录后仍要抽查该分镜，确认节奏正常。

## 动画规则

按 rules.md 的"动效"一节和所选画风文件的动效规则执行。另外：

- **一致性**：同一个人物、物品、地图在不同分镜里使用同一份设计或素材，大小比例和外观保持一致。
- **按布景组织代码**：每个布景写成一个完整的绘制模块（四层都画满，密度见画风文件的"布景密度下限"），分镜只是在布景里设定机位和当时发生的动作。先把布景画满，再写分镜的镜头和动作。
- **招牌镜头先行**：先把分镜表里标出的第一个招牌镜头做出来给用户确认动画质感，确认后再逐个分镜铺开。

## 声音

画面做到哪里，对应的音效事件就记录到哪里：每个分镜把事件（时间、类型、强度、声像）追加到 `audio/sfx_events.json`，供合成音效和混音使用，保证声音和画面动作严格对齐。物理碰撞、步态落脚、大量同类事件（倒下的树）的时刻都由代码直接导出，不靠肉眼估。

配乐用代码编曲时，总谱和动画共用一条时间轴：先挑出 2–4 个关键时刻定速度和起点，让它们落在拍点上。音效合成配方、代码编曲流程和混音都见 audio.md。

## 制作节奏

- **每完成一个布景**：按画风文件的"自查"一节运行 `scripts/frame_check.py`，出对比图、过亮度和对比度门槛，对照密度清单；不通过就改到通过。这一步**任何情况下都不跳过**——用户说"不用给我看、直接做成片"时，省掉的只是请用户查看，自查照做。
- 每完成 3–5 个分镜：运行 `npx hyperframes lint`（必须零错误），截取每个分镜的 2–3 张关键帧，对照 rules.md 和画风文件的禁止清单自查：排版是否拥挤、元素是否遮挡关键信息、文字是否可读、是否出现禁止的样式或没有含义的装饰、暂停测试是否通过。自己修好后，打开 `npx hyperframes preview` 请用户查看（用户说过不用看就不请，自查照做）。
- 用户的风格反馈记进 PROJECT.md 的"风格补充"一节，后面的分镜都遵守。
- 在 TODO.md 里维护分镜完成情况。
